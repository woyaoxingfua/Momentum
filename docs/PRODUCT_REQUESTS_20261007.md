# Momentum 后续产品需求（2026-10-07）

本文记录用户明确提出、尚未实现的两项功能。下列验收口径用于后续实现准备，不代表当前版本已支持。

## 历史常完成任务

用户希望从过去常完成的任务中快速开始新任务。只看当前 `done` 状态不足以重现历史，因为已完成后重新打开的任务不会留在当前完成列表中；应以真实完成历史作为事实来源。

建议的首版口径是：取最近 180 天的真实完成记录，按规范化后完全相同的标题分组；同一标题至少涉及 2 个不同任务 ID 才显示，排除周期任务，并按最近一次真实完成时间排序。展示完成次数与最近完成时间。为避免重开同一个任务反复完成造成虚高，首版按不同任务 ID 计数，不对同一 ID 的多次完成重复加权；不使用模糊标题匹配。

用户确认后，“再来一个”应新建 `todo`，而不是重开或改写旧任务。建议仅复制标题、优先级、估时和标签；不复制截止日期、周期规则、父子/其他关联关系或附件。创建必须走当前用户的任务权限边界；历史列表不能泄漏其他用户的数据。后续实现需核实完成事件字段和幂等/并发创建契约，并分别验证首次完成、重开后再次完成、周期任务排除与用户隔离。

## 任务附件佐证（仅本地暂存）

用户希望在任务列表为任务添加附件佐证，并暂存于本地。建议使用浏览器 IndexedDB 持久保存文件 Blob，而不是 `localStorage`、临时视觉解析上传或新增远端文件服务。附件索引至少绑定当前登录用户身份及任务身份（任务 ID 和创建标识），切换账户或任务后不得显示他人的附件。

首版建议只接收常见图片与 PDF，拒绝 SVG/HTML、可执行文件及压缩包；单文件建议上限 8 MiB，并对浏览器存储配额不足或 IndexedDB 错误给出明确提示，不能静默丢失已有附件。文件名必须作为文本安全显示；预览/打开仅使用本地 Blob。不得把文件内容发往 API、日志、视觉解析服务或 JSON 备份。

界面需明确说明附件只保存在当前浏览器配置文件：清理网站数据可能永久删除，浏览器/设备之间不共享，也不会进入 Momentum 备份；当前方案不加密，不适合存放需要额外保密保护的材料。删除任务时应明确处理并清理其本地附件；保留超时、重试或新任务 ID 变化时不得意外关联到另一任务。

验收至少覆盖：同一任务新增/查看/删除、刷新后仍可见、切换账户隔离、任务删除后的附件清理、超文件大小/配额失败时既有记录不损坏、零上传请求且导出备份不含文件内容。当前版本未实现这些行为。

## 状态与验证边界

截至本文记录时，两项均是需求与建议验收口径，尚无实现、API/schema 变更或浏览器存储实测。后续每次只由一个 owner 改动；本地附件可先保持纯前端，历史常完成任务可能需要服务端完成历史读取，并应单独审查用户隔离、并发与幂等。测试须使用隔离临时数据；不得访问真实 `data/try.db`。
