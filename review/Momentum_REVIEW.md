# Momentum 进展审查与验证摘要

截至 2026-10-07，Momentum 的核心方向是把任务从捕捉推进到专注、完成和复盘。近期前端持续围绕这条闭环完善；Agent、模型和 MCP 是实现手段，不是已证实的产品差异。当前仍是本地审查工作树，未提交或推送。

## 相对远端基线

本次核对时，`master` 的 `HEAD` 与 `origin/master` 相同，均为 `b8cfcfa5e9dd995ff1cf8507d695bba189f7eba0`（2026-07-11）。在该基线上，工作树有 29 个已跟踪文件的未提交差异，合计 6,742 行新增、903 行删除；未暂存或提交。统计只描述当时已跟踪文件的差异，不包括未跟踪文件，也不意味着这些差异都在同一轮生成。

## 当前已具备的能力

任务闭环包括建议卡中的估时编辑、完成和顺延；today-close 可设置截止时间、完成任务或直接开始专注。任务列表支持本地逾期/今日及指定日期筛选、未估时任务清单、快捷补估、短任务优先、直接专注；搜索可与相应筛选组合。Stats 展示今日负载、未来 7 个本地自然日的截止任务分布及可点击的任务清单入口。

Focus 支持按任务估时开始、休息后显式再开一轮、todo 与 doing 任务搜索选择、近期记录及清楚的统计窗口/日期口径说明。统计和复盘以完成事件与真实专注秒数为依据，并区分完成次数、估时和计划时间；任务重开后再次完成会产生新的完成事件。备份恢复、用户隔离的完成/顺延幂等路径、MCP 远程监听鉴权、本地背景图片与主题设置也已形成可用实现。

## 当前质量基线与证据边界

最近一次冻结树唯一全量为 Python **470 passed、11 skipped**，前端 Node **182/182**；52 项 JavaScript/MJS 语法检查、`compileall` 与 diff/whitespace 检查通过。11 项因未配置 `MOMENTUM_TEST_MYSQL_URL` 而跳过，真实 MySQL 未验证。隔离 SQLite/HTTP 与 Chromium 的历史验收确实覆盖了部分完成、顺延、Focus、复盘和设置流程，但不是每次后续静态改动都跑了浏览器；最近的移动工具栏和 Focus 日期说明没有浏览器 E2E 验收。Node/mock、SQLite loopback、真实 MySQL、浏览器 E2E 是不同证据层级，不能互相替代。

专注成功后快照清理**仍不能标记为已修复**。SDK 历史用例 #1 中，旧上下文完成 18 秒结算并收到 200 后，两次 reload 仍出现 18 秒恢复卡；#11 在新 origin 首装路径中，21 秒结算首次 503、同载荷重试 200 后，两次 reload 仍出现 21 秒恢复卡。两项各自的隔离库只有一条完成事件。之后独立 Playwright fresh-context 的 503→同载荷成功→两次 reload 路径通过，快照已结算且没有第三次请求；这不能回溯解释旧上下文的 #1/#11。SDK 对照未完成注册/登录，finish 请求为 0，不是新增失败；v4→v6 同源 Service Worker 升级因缺少可信 v4 工件也未能复现。现有证据不足以判定根因，详见[专注恢复与 #1/#11 附录](Momentum_REVIEW_appendix_20261007.md)。

## 已排定的下一步

先做任务附件的浏览器本地 MVP：附件保存在独立 IndexedDB，按已登录用户和任务身份隔离，只接受图片与 PDF，每件上限 8 MiB，可添加、查看/打开和删除；内容不上传、不进入日志或现有备份。界面须说明仅当前浏览器可用、不同步到其他设备，清除浏览器站点数据会丢失。开始实现前还要核对身份获取方式、IndexedDB 文件空窗，并补刷新、切账号、删除、超限及不上传/不导出的验收。

随后做“历史常完成任务”：按近 180 天真实完成事件，以确定性标准化后的完整标题聚合；至少出现于两个不同任务 ID，排除 recurring，同一任务 ID 的重复完成不加权。用户选择“再来一个”时创建新 todo，只复制标题、优先级、估时和标签，不重开旧任务、不复制截止日期或关系。此项需要完成历史查询能力与独立界面，不能把当前 done 状态列表当作等价功能。
